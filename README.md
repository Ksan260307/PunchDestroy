# PUNCH DESTROY

1,000,000,000,000 個（1兆個）の粒でできた石像を、好きな角度から殴って砕くゲーム。
壊すものは **りんご**・**みかん**・**メロン**・**キウイ**・**ぶどう**・
**バナナ**・**パイナップル**・**さくらんぼ** の8種から選べる。

叩くたびに残りの粒がごっそり減り、穴が開き、内側の金色の芯が顔を出す。
連打が続くとラッシュに入って一撃が跳ね上がり、もろくなった塊は自分から崩れ落ちる。

iPad / iPhone / Android / PC のブラウザでそのまま遊べる。

```bash
npm install
```

```bash
npm run dev
```

## 遊び方

| 操作 | 動き |
| --- | --- |
| **タップ／クリック** | その場所を殴る。**何本の指でも同時に**殴れる |
| **なぞる** | 石像が回る。裏側や底も狙える |
| **長押し** | 溜まりきると渾身の一撃（指ごとに別々に溜まる） |
| **2本指を開く／閉じる** | 寄る・引く。標準の 18 倍まで拡大でき、粒立ちまで見える |

2本指で「叩く」と「広げる」は取り違えない。指の間隔がはっきり変わってから
はじめて寄り引きに切り替わるので、両手でオラオラしても勝手に拡大しない。

パソコンでは **方向キー**で回す、**+ / -** で寄り引き、**Space** で殴る、
**R** でやり直す、**Esc** でタイトルへ戻る。ホイールでも寄り引きできる。

画面右下にラベル付きのボタンが並ぶ:
**音**（入切）／**視点**（向きと拡大を戻す）／**やり直す**／**とじる**（タイトルへ）。
やり直しと終了は、進めたぶんが消えるので一度だけ聞き返す。

立て続けに叩くと **乱打**。1発ごとに**追い打ちが近くへ飛ぶ**ので、
指を増やして速く叩くほど拳の数が増えていく。
乱打は画面には出さず、破壊そのもので見せる。

手を止めなければ連打数が伸び、30 ごとに **ラッシュ**へ。
ラッシュ中は**殴る範囲がちょうど3倍**になり、ひと振りで表面が大きくえぐれる。
残り時間は画面上のゲージで分かる。

残りが 1 割を切ると **総崩れ**。いきなり消えるのではなく、地響きとともに
石像がしばらく震え、粉を落としてから、**下の段から順に**崩れ落ちていく。

全部消すと結果画面。**「今のプレイを見返す」** で同じプレイがそのまま再生される。
スコアの自己ベストは**石像ごとに**端末へ残り、タイトルと結果画面に出る。

### 壊せるもの

| | 見た目 | 削ると |
| --- | --- | --- |
| **りんご** | 赤い塗り面。葉つき | 石の素地、中心に金色の芯 |
| **みかん** | 平たい橙の球。粒立った皮、上に緑のヘタ | 白いわたの下にふさに分かれた果肉 |
| **メロン** | 緑の皮に白い網目。T字のへた | 白い皮の下に淡い緑の果肉 |
| **キウイ** | 産毛の生えた茶色い楕円。両端に小さなヘタ | 鮮やかな緑と、白い芯を囲む種の輪 |
| **ぶどう** | 粒の集まった房。粉をふいた紫。T字のへた | 粒ごとに皮が割れて淡い果肉 |
| **バナナ** | 弓なりに反った黄色い皮。茶色い斑点とへた | 皮のすぐ下から白い果肉 |
| **パイナップル** | ななめ格子のうろこ。葉の冠 | 溝の下に黄色い果肉と白い芯 |
| **さくらんぼ** | 深紅の実がふたつ。Y字の細い柄 | 明るい赤の果肉と、中心の種 |

形は「作り方の指定」を1つ足すだけで増やせる。指定できるのは
輪郭・へこみ・へた・葉・網目・房・曲がった筒・玉の並び・色づかい・当たりの広さと深さ。
中身の量やすき間の多さが形ごとに違うので、当たりの倍率で遊ぶ長さをそろえてある
（同じ調子で叩けば、どれも 110〜170 発ほどで壊しきれる）。
ふさの筋や種の輪のように、削った先の模様は描くときに位置から作るので、
そのためのデータは持たない。

どの石像を壊したかは記録に残るので、見返し再生も正しい石像で再現される。

## iPad で遊ぶ / GitHub Pages へ置く

`main` に push すると GitHub Actions がテストとビルドを流し、GitHub Pages へ公開する
（`.github/workflows/deploy.yml`）。リポジトリの **Settings → Pages → Source** を
**GitHub Actions** にしておくこと。

```bash
git remote add origin https://github.com/<ユーザー名>/PunchDestroy.git
```

```bash
git push -u origin main
```

公開後の `https://<ユーザー名>.github.io/PunchDestroy/` を iPad の Safari で開き、
共有メニューの **ホーム画面に追加** をすると全画面のアプリとして遊べる。

- サブディレクトリ配信でも動くよう、ビルドの参照はすべて相対パスにしてある
- 画面の切り欠き（ノッチ）を避ける余白、二本指ズームやダブルタップ拡大の抑止、
  ホーム画面追加用の設定を入れてある
- 立体表示は WebGL2 を使う（iPadOS 15 以降）。使えない端末では自動的に簡易表示へ切り替わる

## 1兆個をどう扱っているか

粒を1つずつ持つことはしない。石像は **128×128×128 の立体マス目に入れた「残り量」** だけで表す。

- 状態の実体は `Uint8Array` 1本（2MB）。粒の数は `残り量 × 換算値` で作る
- 開始時の合計がちょうど 1,000,000,000,000 になるよう換算値を決めている
- 8×8×8 のマスをひとまとまりの区画として扱い、**空の区画は計算も描画も丸ごと飛ばす**
- 描画は画面の各点から線を伸ばして最初にぶつかった面を探す方式。
  空の区画は粗い占有表でまとめて飛ばすので、実際に調べる点はごくわずか。
  描画命令は1フレームにつき「石像1回＋破片1回」だけ
- 殴ったあと送り直すのは変化した箱の中だけ（1発ぶんで数十KB）
- 材質・「もとの表面からの深さ」・網目の印は1バイトに詰めてある。
  これで塗り面・素地・芯・網目の塗り分けに追加のデータがいらない
- 破片や光は表示側だけの持ち物で、上限を決めて使い回す（毎フレームの確保はしない）

## つくりの決まりごと

進行を決める側（`src/core/`）と、見せる側（`src/game/`）を完全に分けている。

**進行を決める側は、次のものを一切参照しない。**

- 時計・実測フレームレート・端末の性能
- カメラの向きや寄り引き・画面の大きさ・表示設定
- 状態を持つ乱数生成器

ばらつきが要るところは「種・回数・位置」から作る整数ハッシュだけを使い、
計算は整数の足し算・引き算・シフトに閉じている。その結果、

1. **同じ操作からは必ず同じ結果になる。** 記録に残すのは「種」と「いつどのマスを殴ったか」だけ。
   カメラの向きは残さない（当たったマスさえ分かれば十分だから）。
   状態そのものは保存せず、見返し再生はその記録から作り直したもの
2. **処理の順番を変えても結果が変わらない。** 1発の削り量は「その打撃」と「そのマス」だけから決まり、
   いまの残り量を見ない。引き算は 0 で止めるので、どの順に当てても同じ値に落ち着く。
   あとから並列化や処理の間引きを入れても壊れない
3. **表示側が何をしても進行は変わらない。** 演出の量と描画の細かさは実測フレームレートで
   自動的に増減するが、壊れ方も点数も 1 ビットも変わらない

記録には作った時点の版と形の指紋に加えて、**操作の並びそのものの指紋**が入っている。
版が違う記録も、途中が欠けたり書き換わった記録も、黙って再生せずはっきり拒否する。

## ファイル構成

```
src/
  core/            進行を決める側（画面にもカメラにも時計にも依存しない）
    constants.ts   共通の定数
    random.ts      位置から値を作る整数ハッシュ
    shape.ts       石像の作り方の指定と、立体マス目への焼き込み
    world.ts       状態の入れ物・控えの取り方
    rules.ts       状態を1つ進める規則
    trace.ts       線を伸ばして当たるマスを探す（狙いを付ける）
    fingerprint.ts 状態の指紋（照合用）
    session.ts     進行と記録・再生
    view.ts        表示側へ渡す読み取り専用の窓口
  game/            見せる側
    app.ts         進行と表示をつなぐ
    camera.ts      見まわすためのカメラ（寄り引きもここ）
    input.ts       タップ・なぞり・長押し・2本指・キーボードの判定
    effects.ts     破片・光・画面ゆれ
    audio.ts       その場で合成する音
    hud.ts         画面まわりの数字
    storage.ts     自己ベストの保存
    quality.ts     実測速度に応じた演出量と解像度の調整
    render/        描画（立体表示と簡易表示）
tests/             テスト
```

### 遊びやすさのための細かい配慮

- 描く面の大きさは端末が確保できる範囲に自分で抑える。
  端末側で切り詰められると縦横がばらばらに削られて絵が伸びるため、
  縦横比は必ず「実際に描いている面」から取る
- 音は画面のどこを触っても開けるようにし、そのとき実際に音源をひとつ鳴らす
  （携帯端末は「起こす」だけでは開かない）
- ボタンや案内画面の上で始まった操作は殴打として扱わない（押したボタンがきちんと反応する）
- 指の受け取りを固定できない端末でも、2本目以降の指の打撃が消えない
- 携帯端末で画面を閉じている間に音が止められても、戻ってきたら鳴らし直す。
  起こせなければ音の仕組みごと作り直す
- 端末の「視差効果を減らす」設定を見て、画面の揺れと明滅を弱める
- 別のタブから戻ってきたときに時間が飛ばない（時計が戻っても進行は巻き戻らない）
- 殴りそこねたときは軽い音だけ返し、連打は途切れない
- 拡大しているほど、同じ指の動きでもゆっくり回って狙いを付けやすい
- ボタンは指で押しやすい大きさ（44px）にそろえ、キーボード操作時は枠が出る
- やり直し・終了は一度だけ聞き返す（触り間違いで積み上げたものが消えない）
- 保存が使えない環境でも落ちずに遊べる

## テスト

```bash
npm test
```

| ファイル | 何を確かめているか |
| --- | --- |
全 216 件。進行を決める側は全モジュール、見せる側も画面なしで動かせるものは
すべて自動で確かめている。

| ファイル | 何を確かめているか |
| --- | --- |
| `random.test.ts` | ハッシュが同じ入力から同じ値を返し、偏らないこと |
| `shape.test.ts` | **どの石像も**形が毎回同じで、上面がくぼんでいて、粒の合計がちょうど1兆になること |
| `world.test.ts` | 座標と区画の対応、粒の数え方、途中の控えが元どおり戻ること |
| `rules.test.ts` | 削れ方、0 で止まること、集計が狂わないこと、**順番を変えても結果が同じ**こと、**ラッシュの範囲がちょうど3倍**であること |
| `barrage.test.ts` | **立て続けに殴ると乱打に入る**こと、追い打ちの数と散り方、順番に依らないこと |
| `finale.test.ts` | **震えている間は崩れない**こと、そのあと下の段から順に崩れること、崩れ方が毎回同じこと |
| `trace.test.ts` | どの向きから狙っても表面に当たること、穴を開けた先を狙えること |
| `fingerprint.test.ts` | 同じ中身から同じ指紋、1マス違えば別の指紋になること |
| `session.test.ts` | 記録から完全に作り直せること、**版・石像・中身が食い違う記録を拒否**すること、控えからの再開が一致すること |
| `view.test.ts` | 表示側からは書き換えられないこと、ラッシュの残りが正しく減ること |
| `camera.test.ts` | 写した点をたどると元へ戻ること、**18 倍まで寄っても石像の中へ入らない**こと |
| `input.test.ts` | **指の数だけ同時に殴れる**こと、叩くと広げるを取り違えないこと、長押し・なぞり・キーボード |
| `effects.test.ts` | 破片が上限を超えないこと、揺れが収まること、文字が溜まらないこと |
| `quality.test.ts` | 遅くなったら演出を減らし、戻れば増やすこと |
| `audio.test.ts` | 止められた音を起こし直せること、**起こせなければ作り直す**こと |
| `storage.test.ts` | 自己ベストを**石像ごとに**覚えること、壊れていても保存できなくても落ちないこと |
| `isolation.test.ts` | 演出の量・揺れ・時計・乱数・カメラを変えても進行が変わらないこと |
| `purity.test.ts` | 進行を決める側のソースに時計や乱数が混ざっていないことをソース走査で確認 |
| `playthrough.test.ts` | **どの石像も**最初から最後まで壊しきれること、速く連打するほど早く終わること、形ごとに殴る回数が偏らないこと |

画面や描画装置が要るもの（HUD の組み立て、立体表示、ボタンの配線）は
自動テストの対象外で、ブラウザで動かして確かめている。
